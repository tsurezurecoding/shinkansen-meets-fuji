# CINEMA intro player

Integrated from the approved local HTML candidate on 2026-09-26 and updated by the subsequent TOP playback fixes. After preparation, the visible hero waits 1.2 seconds before the original CINEMA film (with a 1.6-second phone hold), then returns to the home heading instead of the closing URL card and waits 8 visible seconds before repeating. Silent. The 49-second standalone bilingual player remains available at `player.html?film=ja|en`. Android is not promoted in the film.

Runtime source: `player.html`, `film.js/css`, `cinema.js/css`, `night-cut.js/css`, shared `pv-engine.js` and `pv-base.css`, `player.js/css`, `embed.js/css`, `scenes.js`, and `assets/`. These are the editable production sources. The earlier comparison prototypes are not runtime dependencies.

All photographs are michikusa's own. Captured product screens contain no third-party photographs; map attribution is retained. Lightweight source provenance and hashes are preserved in the operating repo at `.codex-local/previews/promo-pv-html-0926/assets-report.json` and `night-assets.json`. The source storyboard and inherited render history are documented there. Original synthesized audio only, no station melody.

Marketing count is `50+` in the film, its transcript and reduced-motion cards. TOP uses “50以上の景色” / “50+ views”. Adding a spot does not require edits. The source data remains authoritative for actual list totals. Night illumination/berthing footnotes are intentionally omitted from this introduction at the owner's request.

The hero runtime is `../hero-cinema.js/css` and `hero-stage.html/js/css`. The static home heading, description, poster and four entry cards live in `../index.html`; English is generated by `scripts/generate-spot-pages.mjs`. `hero-stage.html` owns the copied stage markup and reuses the unchanged film renderers. Keep stage DOM IDs aligned with `player.html` when updating the renderers. No preview directory is a runtime dependency.

The parent poster and iframe hero use matching 960w/1920w variants of the same existing michikusa photograph; the browser selects the resolution, with the full image retained on larger/high-density displays. The first photo is not lazy-loaded. This reduces initial poster bytes, not necessarily bytes for the whole film, whose later scenes may request the full-size photograph. Existing entry-card thumbnails use native lazy loading; the lower journey-strip photographs keep their existing loading behaviour pending isolated performance evidence.

The initial and repeat hero waits use a cancellable timer rather than an animation-frame loop. Offscreen/hidden/pagehide cancels it and preserves the remaining visible wait; explicit pause cancels it, and manual play remains immediate. Animation frames run during playback and chapter transitions. Letterbox colours follow the renderer's inline background except for the CSS-defined finale, with repeated colour reads cached. The existing nominal wait durations, automatic repeat, reduced-motion/Save-Data handling and analytics are unchanged. Regression coverage is in `scripts/hero-stage.test.mjs`.

TOP's non-hero editorial sections use `content-visibility: auto` to defer offscreen layout, retaining their real HTML and links. A remembered intrinsic size avoids collapsing unrendered sections; printing restores normal rendering. The hero and entry cards are excluded. Do not replace this with hidden content or interaction-triggered HTML loading.

The stage is a noindex utility iframe, not a new editorial landing route. TOP passes language with `?film=ja|en`. Manual chapter navigation preserves an explicit pause; otherwise playback continues automatically. Arrow, pointer swipe, horizontal wheel and keyboard navigation are supported. The hero does not run offscreen or in hidden tabs. Reduced-motion and Save-Data keep the initial poster without loading the iframe until a manual request; selected chapters are still images. A saved explicit pause is retained in sessionStorage by the parent. Failure leaves the real HTML heading and entry cards usable.

TOP no longer starts the `intro_film_*` dialog events. The new `hero_film_chapter` (chapter and input method) and `hero_film_auto_complete` events use the existing consent-aware gtag only when available. Entry cards retain `lp_cta_click` and value-path events; train selection is `hero-card-train`. These describe use, not satisfaction or causal effect. The retired `intro-film.js/css` are not loaded or distributed by the TOP; the standalone player keeps its explicit sound control.

Runtime files are registered by `scripts/generate-content-manifest.mjs`. Android bundling is a separate follow-up; do not synchronize the new TOP into mobile without registering the dependencies and checking the app's webview behavior.
